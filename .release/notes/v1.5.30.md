# 1.5.30

## 中文

这一版是「按真实小说跑通全流程」之后修出来的一版，主要修 1.5.29 发布后发现的问题。

### 修复：升级后旧项目打不开

1.5.29 给蓝图加了 `costs_and_turns` / `foreshadowing` 两列，但那次改动顺带改变了版本 1–7 的规范 schema 指纹，却没有配迁移步骤。结果任何用 1.5.28 建的项目（包括《源起》）都会被判成「无法识别项目格式」，**完全打不开**。

- 新增迁移 **M07**（7 → 8），幂等地补上两列；M00 的基线重新冻结，历史指纹保持不变。
- 老项目现在能正常识别并升级到 v8，作者内容（粗纲、细纲、正文）逐字保留。
- 顺带修好「canonical 项目升级白名单只到 v6」的问题：v7 项目原本也无法升级。

### 修复：检查结果不显示 / 一直像没反应

- AI 检查是异步工作流，之前点完「开始检查」只登记了任务就立刻重读结果，于是永远显示「还没有检查结果」。现在会**等运行结束再自动加载**，并在等待期间显示「正在检查…」。
- 检查面板不再因为页面重读而被卸载（那会把进行中的状态一起丢掉）。
- 面板自己跟踪运行中状态，宿主忘记回传也不会让按钮看起来没反应。

### 修复：功能表反而让项目打不开

- AI 检查的建议表是首次使用时才建的。它们原本不在「功能扩展表」白名单里，导致**用过一次检查之后，项目指纹变化、下次就打不开**。现已加入白名单，并补了守护测试：任何懒建表都不得改变项目指纹。

### 修复：蓝图检查的建议是空的

- 蓝图检查返回的 `expectedText` 是字段补丁对象，之前的归一化只接受字符串，于是全被丢成空串，卡片上的「接受」等于没反应。现在对象会被序列化保留，`characters` 字段也会正确转成数组。

### 修复：细纲检查写回失败

- 模型常把六个小节写成 `### 小标题`，而正式细纲是扁平格式，严格校验会拒绝写入。现在提示词明确要求扁平写法，同时在写回前把 `### 小节名` 归一化成「小节名：」。
- 写回失败时不再只显示「写回原文失败」，而是给出具体原因。
- 同一条建议的整段替换只会写一次，避免重复应用。

### UI 修正

- 细纲的 AI 检查面板移进「细纲」这一节，和粗纲、蓝图一致，不再浮在页面顶部。
- 检查卡片的定位标签按层区分：粗纲显示「第 N 段」，细纲 / 蓝图显示「第 N 章」。
- 范围选择弹窗的按钮改成「确定范围」，不再让人以为点一下就开始检查。
- 单次检查最多 50 章，默认范围也限制在这之内，避免一次把整本书塞进模型；超出时给出明确提示。

### 验证

- 在《源起》（3000 章、20 段粗纲、270 章细纲）上真实跑通：粗纲检查 → 接受写回、细纲检查 → 按章写回、蓝图生成 → 检查 → 接受写回、第 1 章正文生成。生成的第 1 章正文确实带上了蓝图里的代价与伏笔（源起债 1200、门牌降级、待回收样本、占位符「源起」）。
- 迁移测试 121 项通过（含新增的 M07 与真实库回放）。
- 全量浏览器回归：81 个测试文件、963 项测试通过。
- 类型检查、lint、i18n 覆盖率检查全部通过。
