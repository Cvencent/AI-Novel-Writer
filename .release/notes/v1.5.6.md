# 1.5.6

## 中文

这一版修好三件事：日志看不到 Prompt、粗纲只能从头看、情节大纲没有目录。

### 日志：每次调用都记 Prompt，并可回收空间

- 以前的日志只在导入、短纲、情节大纲这几类任务上记录完整 Prompt，粗纲、角色细节、世界观、核心种子这些一律没记——所以你打开日志只看到返回文本，工具调用也是空的（那些任务本来就不走工具，不是丢了）。
- 现在**每次调用都记录完整 Prompt**，日志里能回看模型到底收到了什么，包括 system 与 user 消息全文。
- 代价是体积：大纲类调用的用户提示词会带上已确认大纲的上下文，单次可达 MB 级。所以配套一条保留策略：**只保留最近 200 次调用的完整 Prompt**，更早的会清掉 Prompt、保留返回文本、用途、模型与 token。被清掉的记录会在列表和详情里明确标出「Prompt 已按保留策略清理」，不会伪装成一条空记录。
- 清理以后 SQLite 不会自己把文件缩小，要 VACUUM 才行。在 477MB 的库上实测要十几秒，绝不能挡在打开作品的路上。所以设置里新增了「项目维护」页：显示当前占用，由你明确点一次「回收空间」。
- 实测《源起》：`743 次调用 · 639 次带 Prompt（353.3 MB）` → 点回收 → 耗时 9.9 秒 → `200 次带 Prompt（93.8 MB）`，**数据库文件 477.7 MB → 216.3 MB**。正文与大纲完全不受影响。

### 粗纲：右侧按段列出，点哪段看哪段

- 以前打开粗纲只能从第 1 章往下滚。现在标签页右侧有段列表，显示每一段的区间与标题（例如「第 191–310 章：记忆的倒影」），点一下就跳到那一段。
- 实测《源起》：3 段（1–60 / 61–190 / 191–310），点最后一段能准确跳到该段标题。

### 情节大纲：右侧按章列出

- 情节大纲同样加了右侧目录，按章列出。508 章的作品点最后一章能直接跳过去，不用滚几万字。

### 验证

- 浏览器测试 79 文件 / 945 项全过；生成与运行相关的 Node 测试 1369 项通过（另有 1 项既有失败与本版无关，在改动前的干净版本上同样失败）。
- 类型检查、lint、i18n 检查通过。
- 端到端在打包前的真实构建上验证：日志展开能看到「完整 Prompt」与 user 消息；粗纲 3 段与情节大纲 508 章都能点开跳转；回收空间后数据库从 477.7 MB 降到 216.3 MB。

升级不改动作品数据。已经产生的旧日志不会自动清理，想回收请到「设置 → 项目维护」。

Windows 安装包未签名，系统可能提示未知发布者。

## English

This release fixes three things: prompts missing from the log, arc outline only readable from the top, and no contents list for the plot outline.

### Logs: every call records its prompt, and space can be reclaimed

- The log only recorded full prompts for imports, short outlines and plot outlines; arc outlines, character details, worldbuilding and core seeds never recorded one. That is why you only saw responses, and why tool calls were empty (those tasks do not use tools at all — nothing was lost).
- Now **every call records its full prompt**, including the complete system and user messages, so you can see what the model actually received.
- The cost is size: outline calls carry the confirmed outline context, which can reach megabytes per call. So there is a retention policy: **only the most recent 200 calls keep full prompts**; earlier ones lose the prompt but keep the response, purpose, model and tokens. Trimmed records say so explicitly in the list and detail view, instead of looking like empty records.
- After trimming, SQLite does not shrink the file on its own — that needs VACUUM, measured at around ten seconds on a 477 MB database. It must never block opening a book, so Settings now has a **Project maintenance** page showing current usage, with an explicit "Reclaim space" action.
- Measured on 源起: `743 calls · 639 with prompts (353.3 MB)` to reclaim, taking 9.9 s, resulting in `200 with prompts (93.8 MB)` — **the database file went from 477.7 MB to 216.3 MB**. Your text and outlines are untouched.

### Arc outline: a segment list on the right

- The arc outline used to only be readable by scrolling from chapter 1. The tab now has a segment list on the right showing each segment range and title (for example "Ch. 191-310: Reflection of Memory"); clicking one jumps to it.
- Measured on 源起: 3 segments (1-60 / 61-190 / 191-310), and clicking the last one lands exactly on that heading.

### Plot outline: a per-chapter list

- The plot outline got the same contents list, one entry per chapter. In a 508-chapter book, clicking the last chapter jumps straight there instead of scrolling past tens of thousands of characters.

### Verification

- 79 browser test files / 945 tests pass; 1369 generation and run related Node tests pass (one pre-existing failure is unrelated and fails identically on clean pre-change code).
- Typecheck, lint and i18n checks pass.
- End-to-end on the real pre-package build: the log expands to show a full prompt with user messages; the 3 arc segments and 508 outline chapters all jump correctly; reclaiming space dropped the database from 477.7 MB to 216.3 MB.

Upgrading does not touch project data. Existing logs are not trimmed automatically — use Settings then Project maintenance to reclaim.

The Windows installer is not code-signed; Windows may warn about an unknown publisher.
