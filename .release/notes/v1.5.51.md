# 1.5.51

## 中文

### 修复：一次打包会污染测试环境，跑测试全线报「NODE_MODULE_VERSION」

- `electron-builder` 打包时会把 `better-sqlite3` 重编译成 Electron 的 ABI。完整的发布门禁（`build:win`）在收尾步骤会把模块恢复成普通 Node 可用的状态，但单独跑 `build:win-dir` 或 `build:win:artifacts` 打完包就结束了——模块留在 Electron ABI 上，之后任何人执行 `pnpm test`，所有需要 SQLite 的测试（128 个文件、约 1700 个用例）加载原生模块即告失败。
- 现在 `build:win-dir` 与 `build:win:artifacts` 在打包完成后自动执行 `prepare:native-node`，把模块恢复回 Node ABI；打包契约测试锁定了这一行为。

### 修复：细纲生成遇「长度截断」整批中断，不再按设计重建

- 细纲逐章生成时，主进程持账的模型轮次遇到 `finishReason=length`（AI 输出达到本次请求长度上限）会直接抛错，把整批细纲打断。而游标设计本来的意图是：同一章先按 normal 尝试，长度截断的候选保留后自动发起一次原事实重建（compact），重建仍失败才停下交给恢复入口。
- 恢复了这条链路：大纲轮次的有界失败不再当场抛出，候选落库后交回游标判定，长书重建与「保留两次失败候选」的恢复语义同时恢复。

### 修复：逐章细纲丢失作者的步骤指导

- 上次重构把逐章细纲的提示词换成了固定事实合同，但作者的「本步骤额外指导」（例如「结尾必须归还借来的钥匙」）没有跟着搬进去，被静默丢弃。现在每次章节大纲请求都会带上这条最高优先级的作者指导。

### 修复：用过「粗纲」的项目无法导出便携包

- 粗纲的两张惰性表（`arc_outlines`、`outline_segment_bindings`）没有登记进便携字段契约，任何生成过粗纲的项目导出时都会报 `PORTABLE_SCHEMA_UNSUPPORTED`。现在两张表按可选表登记：项目里有就逐字段严格校验，没有就跳过。

### 修复：M07/M08 之后，被篡改的角色身份数据不再被打开校验拒绝

- 迁移 registry 的 verify 链在 M07、M08 两步只校验 schema 指纹，丢掉了前几步一直保留的 M02 角色身份复核（`verifyM02CharacterIdentity`）与 M03 审稿周期复核。结果一个 `character_aliases.valid_from` 被改成非法值的数据库，打开时不再报 `MIGRATION_VERIFICATION_FAILED`。两步的校验链已按 M04–M06 的既有模式补回。

### 维护

- M02 迁移证据的 preIdentity 域排除 M07 新增的蓝图扩展列，避免「升级前/升级后」证据因投影列不同而误报内容变化。
- 同步一批随合约演进的测试：M07 蓝图扩展列进夹具、细纲默认字数 600→300（v1.5.16 起生效，含 r3 协议文件）、新输出六小节接受闸门进夹具、蓝图合同必填 `costsAndTurns`/`foreshadowing` 进夹具、项目预览按当前 schema 建夹具、LLM 设置删除模型的新 IPC 回执。
- LanceDB 冷启动在并行全量跑时可能超过默认 5 秒，相关知识库测试放宽到 30 秒，消除误报超时与其级联的 `GENERATION_KNOWLEDGE_BUSY`。

## English

### Fix: packaging polluted the test environment — `pnpm test` failed en masse with NODE_MODULE_VERSION

- `electron-builder` rebuilds `better-sqlite3` for the Electron ABI while packaging. The full release gate (`build:win`) restores the Node ABI in its finalization steps, but standalone `build:win-dir` / `build:win:artifacts` ended right after packaging, leaving the module on the Electron ABI — every SQLite-dependent test file (128 files, ~1700 tests) then failed at native load.
- Both scripts now run `prepare:native-node` after packaging; the packaging contract test pins this behavior.

### Fix: a length-truncated outline chapter aborted the whole batch instead of rebuilding

- During per-chapter outline generation, a main-owned model round that ended with `finishReason=length` threw immediately and killed the batch. The cursor design intends the opposite: keep the truncated candidate, automatically rebuild the chapter once from original facts (compact), and only then stop into recovery.
- The chain is restored: bounded failures in outline rounds no longer throw; the artifact is persisted and the cursor decides the next step.

### Fix: per-chapter outlines silently dropped the author's step guidance

- The chapter-outline prompt rebuild lost the per-step author guidance (e.g. "the ending must return the borrowed key"). It is now injected into every chapter outline request with highest priority.

### Fix: projects that used arc outlines could not be exported

- The two lazy arc tables (`arc_outlines`, `outline_segment_bindings`) were missing from the portable field policy, so any project that generated an arc outline failed export with `PORTABLE_SCHEMA_UNSUPPORTED`. They are now registered as optional tables: strictly validated field-by-field when present, skipped when absent.

### Fix: tampered character identity data no longer rejected at open after M07/M08

- The migration registry's verify chain for M07 and M08 only checked schema fingerprints and dropped the M02 identity re-verification (plus M03 review-cycle verification) that earlier steps kept. A database with `character_aliases.valid_from` tampered no longer failed with `MIGRATION_VERIFICATION_FAILED`. Both steps re-verify per the M04–M06 pattern.

### Maintenance

- M02 migration evidence excludes the M07 blueprint columns from the pre-identity domain so before/after comparisons no longer flag projection-only differences.
- Synced tests that drifted from their contracts: M07 blueprint columns in fixtures, the outline default target units 600→300 (effective since v1.5.16, including the r3 protocol file), the six-section acceptance gate in fixtures, required `costsAndTurns`/`foreshadowing` in blueprint fixtures, project-peek fixtures at the current schema, and the new `llm:get-function-models` IPC in the LLM store boundary test.
- LanceDB cold start under a parallel full run can exceed the default 5s; knowledge-base tests were relaxed to 30s to remove spurious timeouts and their cascading `GENERATION_KNOWLEDGE_BUSY`.
