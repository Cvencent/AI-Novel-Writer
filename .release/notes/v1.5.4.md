# 1.5.4

## 中文

这一版把粗纲真正接进整个流程：按钮能用、缺粗纲时主按钮直奔粗纲、写入与确认后全页同步，并把流程脊的节数对上。同时修掉一个仓库级问题。

### 「生成下一段」现在真的会用

- 上一版把粗纲并进架构页时，节头那颗按钮接的是一个空操作：点了既不启动工作流，也不会出现运行侧页。现在它直接接到粗纲面板里那同一份生成逻辑（模式判断、按段推进、等运行结束都在一处），节头点与面板里点走的是同一条路。
- 因此右侧运行侧页（和顶栏的运行胶囊）也随之恢复：以前因为没有工作流真正启动，侧页一直没有数据可显示。

### 只差粗纲时，主按钮直接生成粗纲

- 五节里唯一没确认的是粗纲时，主按钮过去仍写「继续生成架构」，点开的是一个**补不了粗纲**的对话框（那个对话框只覆盖四节）。现在这种情形主按钮写「AI 生成粗纲」，点了直接走粗纲的分段流程。
- 顺带把页头文案里的「四节」全部改成「五节」（引导语、下一步按钮的提示）。
- 粗纲写入、确认或改写之后，节徽标、页头计数、主按钮与左侧流程脊现在会一起刷新（以前只刷新粗纲面板自己的列表，确认后流程脊会停在旧数字）。
- 日志页对旧记录更稳：缺少工具调用等字段的调用记录过去会把整页打崩，现在只让对应区块不显示；读不到详情时说明「没有可显示的记录」，不再一直停在「正在读取」。

### 流程脊按 5 节算

- 流程脊原本仍按 4 节计算（故事前提 / 角色名单 / 世界观 / 情节大纲），粗纲不在其中，于是显示成「架构 3 / 4」。现在粗纲计入，显示「架构 N / 5」。
- 粗纲的确认判定与节里的徽标一致：至少有一段、且每一段都已确认。

### 验证

- 在《源起》实测：点粗纲节的「生成下一段」，运行侧页出现（「生成粗纲 · 开始 · 0%」），顶栏运行胶囊出现；点「查看粗纲」能打开「架构 / 粗纲」标签并读到分段全文；流程脊显示「架构 4 / 5 已确认」。
- 浏览器测试 78 个文件 / 940 项全过（含架构 35 项、日志 7 项），另有导航、架构、大纲相关的 610 项 Node 测试通过；类型检查、lint、i18n 检查通过。整套架构场景也在**打包后的 1.5.4 应用**上跑通（`--exe`）。
- 在打包产物上端到端跑了一遍本版的新交互：五节顺序与徽标正确；只差粗纲时主按钮写「AI 生成粗纲」且不打开架构对话框；点它启动工作流、运行侧页出现「生成粗纲 · 进行中」；段落产出后写进粗纲一节并显示「1 段 · 已确认 0 段 · 到第 20 章」；点「确认此段」后徽标变「已确认」、流程脊从 4 / 5 变 5 / 5、主按钮变「下一步：章节蓝图」。
- 另外修了一个仓库问题：`.gitignore` 里的 `logs` 规则把 `src/components/stage/logs/` 一起忽略了，生成日志页其实从来没进过 Git —— 新克隆根本编译不过。规则已收窄成 `/logs/`。

升级不改动作品数据。

Windows 安装包未签名，系统可能提示未知发布者。

## English

This release wires the arc outline into the whole flow — working buttons, a primary action that goes straight to the arc outline when it is the only gap, and full-page refresh after writes and confirmations — and lines the stage spine up with five sections. It also fixes a repo-level problem.

### "Next segment" actually generates

- When the arc outline moved into the architecture page, the section-header button was wired to a no-op: clicking it neither started a workflow nor produced a run sheet. It now calls the same generation logic the panel itself uses (mode handling, segment-by-segment advance, waiting for the run), so the header and the panel take one path.
- The right-hand run sheet (and the run capsule in the header) comes back with it: previously no workflow ever started, so there was nothing for it to show.

### The spine counts five sections

- The stage spine still counted four sections (premise / cast / world / plot outline), leaving the arc outline out and reading "architecture 3 / 4". The arc outline is now counted, so it reads "architecture N / 5".
- Its confirmation test matches the section badge: at least one segment, and every segment confirmed.

### Only the arc outline missing generates it directly

- When the arc outline was the only unconfirmed section, the primary button still read "Continue architecture" and opened a dialog that **cannot fill in the arc outline** (that dialog covers four sections). It now reads "Generate arc outline" and starts the arc's own segmented flow.
- Page copy saying "four sections" (lede, next-step button tooltip) now says five.
- After the arc ledger is written, confirmed or rewritten, the section badge, header count, primary button and the left-hand stage spine now refresh together (previously only the panel's own list refreshed, so confirming left the spine on a stale number).
- The log page is more forgiving of old records: a record missing e.g. tool calls used to crash the whole page; now only that block is hidden, and a call with no readable detail says so instead of showing "loading" forever.

- Verified on 源起: clicking "Next segment" in the arc section brings up the run sheet ("Arc outline · started · 0%") and the header run capsule; "View arc outline" opens the Architecture / Arc outline tab with the full segmented text; the spine reads "architecture 4 / 5 confirmed".

- Verified on 源起: clicking "Next segment" in the arc section brings up the run sheet ("Arc outline · started · 0%") and the header run capsule; "View arc outline" opens the Architecture / Arc outline tab with the full segmented text; the spine reads "architecture 4 / 5 confirmed".
- 78 browser test files / 940 tests pass (including 35 architecture tests and 7 log tests), plus 610 Node-side navigation/architecture/outline tests; typecheck, lint and i18n checks pass. The full architecture scenario suite also passes against the **packaged 1.5.4 build** (`--exe`).
- End-to-end on the packaged build: five sections and badges are correct; with only the arc outline missing the primary button reads "Generate arc outline" and does not open the architecture dialog; clicking it starts the workflow and the run sheet shows "Arc outline · in progress"; the produced segment lands in the arc section as "1 segment · 0 confirmed · through ch. 20"; clicking "Confirm" flips the badge to confirmed, the spine from 4 / 5 to 5 / 5, and the primary button to "Next: chapter blueprint".
- Also fixed: the `.gitignore` rule `logs` was swallowing `src/components/stage/logs/`, so the generation-log page had never been committed at all — a fresh clone would not build. The rule is now scoped to `/logs/`.

Upgrading does not touch project data.

The Windows installer is not code-signed; Windows may warn about an unknown publisher.
