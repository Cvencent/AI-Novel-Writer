### 1.5 内容类 issue 的第一道判断：机制 还是 模型输出（用户 2026-11-03 明确要求）

`[text]` / `[content]` 类 issue（正文写法的收敛、重复、走形）**先判断这到底是哪一类**，
再决定动不动代码——**这是动手前必须过的一道门**：

| 判据 | 结论 |
|---|---|
| **机制的锅**：程序本可以判定/统计，但**漏了、取错了对象、写错了数**（如 #119 把上一句的引号单字当成本句偏旁名的描述对象；如 #114 判据只封上限、趋势看不出来） | **改机制** |
| **模型输出的锅**：这是「写得好不好」的偏好，程序没有可靠办法在不写死词表的前提下判它 | **不改代码**——回帖说明「判为模型输出」，然后**关闭** |

**改机制时的硬约束（用户原话）：必须做成通用的，不许把短语写死。**

- 判据要**结构性**：靠语法类 / 位置 / 分布 / 数据表（如 #99 用康熙部首表、#81 用最长公共子串、
  #111 用「句首是否有人 + 是否含未完结标记」），**不是**枚举本项目某本书碰巧出现的那些短语。
- ⚠️ **反面例子（本轮实际踩到并已撤回）**：#117「笑容定格」曾加过 `EXPRESSION_PHRASES
  = ['笑停在脸上','笑还挂着','笑没落',…]`。这类表**只对这一本书有效**，换本书立刻失效，
  正是本仓在 #30/#43/#70/#80/#93/#96/#99 反复吃过的词表过拟合。实测想换成通用判据也不成立：
  逐字短句跨章复现 0 命中（现象恰恰是「**换措辞**说同一件事」）、剥人名后按最长公共子串聚类
  出一堆「看了一眼」「他往下压」（噪声）、5–8 字的拍点远低于能安全判重的长度。**结论：判为模型输出。**
- 判断顺序建议：先问「**不写词表**，我能不能用结构/位置/分布把它判出来」；
  答不出「能」就说明这是偏好问题 → 按模型输出处理，别硬塞一个词表交差。
- 已经写了词表的**立刻撤回**（`git revert`），并在评论里写清为什么。

### 1.6 规则只能做一半时，剩下的**交给模型**——不要到处堆强规则（用户 2026-11-04 明确要求）

**用户原话**：「你解决问题的时候，要看有的东西是不是规则做不完整，是需要模型介入的地方。
不要每个地方都写强规则。」

这条是 §1.5 的**另一半**。§1.5 讲「什么不该用规则做」，这条讲「规则做不完的那一段该交给谁」：

| 这一段适合谁 | 判据 | 例子 |
|---|---|---|
| **规则** | 结构性、可穷举、有唯一答案：分派、可写性判断、格式校验、差异比对、事实登记 | #137 的「这条提醒属于哪一层」「现在能不能改」；#127 的 `assembleMergedText`（全取原稿==原稿 可断言） |
| **模型** | 要「写出来」才有答案：改写、补写、换措辞、按约束重生成 | #137 的「把这条提醒按建议改掉」——判据给的 `suggestion` 是自然语言改法，**规则无法把它落到具体字段**，只能让模型写 |
| **作者** | 取舍与偏好：要不要改、改成什么样算好 | 差异确认必须由作者点，不能自动落库 |

**落地要求**：

- 判据层只做**能断言的**那部分，把「需要生成」的部分显式做成一次模型调用（一次调用处理**同层的一批**
  reminders，不要每条一次），产出走**字段级 patch**（只含变化字段），再由作者确认差异后落库。
- ⚠️ **反面做法**：为了「不用模型」而给每个判据写一条硬规则式的自动修补（例如按 `suggestion`
  里的固定句式用正则去改正文）——这类规则只对本项目某本书成立，等于换个地方写词表。
- ⚠️ 也**不要**把「规则做不完」当成「什么都交给模型」的借口：分派/可写性/差异/校验这些
  **能确定的必须确定**，模型只负责**生成内容**那一格。否则模型会把「不该改的层」也改了，
  而作者看不到为什么。
- 判断顺序：① 这条断言能用结构判出来吗 → 能就写规则；② 判不出来但只需要一次自然语言生成 → 交模型；
  ③ 连「什么算改对了」都说不清 → 交作者（给差异，不给自动采纳）。

### 1.7 「内容判断」一律交模型——**不许词表、不许短语匹配、不许任何写死的内容逻辑**（用户 2026-11-05，两轮追加）

**用户原话**：「不要有这种写死的标记词…不要有任何写死的这种内容的逻辑。内容全让模型去处理，懂吗？
你只负责让模型怎么去生成。」

这条比 §1.6 更严，先看一个**我实际交付过、又被用户当场否掉**的例子（#153 的 `body-mark-consistency.ts`）：

```ts

const BODY_PARTS = ['无名指','小指','拇指','食指','中指','虎口','肩','腿','脚','掌','手']
```
我当时的理由是「这是**封闭词类**，不是短语表」——评委（用户）的判断是**不行**：
它仍然是「拿一张我写的词表去替模型判断内容」。用户要的是**内容判断全部交模型**。

| 这一层 | 谁做 | 允许写什么 |
|---|---|---|
| **程序**（`src/`、`electron/`） | 分派、可写性、格式校验、差异计算、事实登记、**调用模型** | 结构、位置、计数、哈希、schema。**不含任何内容词表** |
| **模型** | 一切「这段内容对不对/像不像/有没有」的判断 | 判据提示词（问什么、要什么形状的答案） |
| **作者** | 取舍 | 差异确认 |

**落地要求（改判据时按这个顺序想）**：

1. **先问**：这条判断能不能改写成「**给模型的一段问句 + 一个结构化答案**」？
   能 → **就这么做**，不要先去设计词表。模板见 `src/shared/preflight-repair.ts` 的
   `buildRepairPrompt`（问什么、要不要 JSON、越界如何整条拒绝）与
   `src/services/workflows/commands/*.command.ts` 的 `operation/promptKeys` 接线方式。
2. **确实无法交模型**的（例如「这条提醒属于哪一层」），才写规则；写的时候只允许用
   **结构/位置/语法形态**，并且**不得出现任何具体词语**。
3. **已经写了词表的判据**：本轮必须以「改成模型判断」为目标处理；来不及改就在评论里
   明确写「这条带词表、待改成模型判断」，不要当成交付完成。
4. ⚠️ 自查一句话：**把这个文件里的所有引号字符串删掉，判据还成立吗？**
   不成立就说明它靠词表在工作。

**为什么（用户给出的理由，比自己想的有力）**：
- 我的词表只对**这一本书**成立；换本书立刻失效（本仓 #30/#43/#70/#80/#93/#96/#99 反复吃过）。
- 我的词表还会**悄悄判错**：#153 那套「从标记词往回找部位」在「右手虎口留着一道旧疤」
  上是对的，但换一句写法就会抽错对象——而我没有任何办法穷举中文的写法。
- 模型本来就在这条链路上（起草、审稿都要它），让它判一次的成本远低于我维护一张词表。

**代价（要如实承认）**：改判据会把「确定性判据」变成「模型判据」——不是每次结果都一致、
需要 ack/豁免机制承接、还要防止它把「没问题」也说成有问题。所以：
- 模型判断的产出必须走**作者确认**（差异/候选），**不能自动落库**；
- 提示词里必须写明「只报你能举出原文证据的，不确定就不报」（与审稿合同的写法一致）。

#### 1.7.1 禁令的**准确范围**（用户 2026-11-05 第二次补充，比上面更严）

**用户原话（第二轮）**：「不要有任何那个内容上的文字类的写死的判断逻辑，不能去设计词表，
也不能用任何的短语匹配，就是不能有这类的逻辑，内容类的全部让模型判断。」

三句话三条禁令，逐条对应本仓的具体形态：

| 禁令 | 本仓的具体形态（**都不许再写**） |
|---|---|
| **不许词表** | `const X = ['腥气','霉味',…]`、`const Y = /缺\|断\|疤\|伤/`、`Object.freeze([...])` 里的题材词 |
| **不许短语匹配** | `content.includes('那句话')`、`new RegExp('不改口\|不松口')`、`prose.indexOf(某句)` 当作「发生了这件事」的证据 |
| **不许任何写死的内容逻辑** | 用「同一个词出现 N 次」「某词在句首」「某词后 8 字内」这类**形状规则**去断言内容语义 |

**⚠️ 划界（这条最重要，别把整仓判死）**：禁令针对**内容语义**——「这句话说了什么、说得对不对、
是不是同一件事」。**不针对**下列这些「不需要理解内容」的东西，它们仍**必须**由规则做：

| 仍然由规则做 | 为什么 |
|---|---|
| 分派 / 可写性 / 路由（`preflight-route.ts`） | 键前缀 → 层，是**约定**不是语义 |
| 格式与结构校验（JSON 形状、字段白名单、长度上限、偏移/哈希） | 可断言、有唯一答案 |
| 计数与分布（章数、条数、字数、「≥3 章」「跨度 ≥8」） | 是统计量，不是内容 |
| 引文定位（`indexOf`/唯一性）、差异计算（`assembleMergedText`） | 位置与字节，不是语义 |
| **语法/符号类封闭集合**：引号族、句末标点、设问/感叹、康熙部首表、时间单位、序数词 | 语言**形式**，不是题材内容 |

**判断口诀（改判据时念一遍）**：

> 我要断言的是「**这段文字说了什么**」→ **交模型**。
> 我要断言的是「**这段文字的形状/位置/数量**」→ 可以写规则，且规则里**不许出现题材词**。

**已列出的待改清单（本轮盘点，写在评论里跟踪）**：
`sensory-channel`（气味词）、`prose-repetition`（三族短语）、`prop-termination`（终结动词表）、
`prose-flavor`（比喻连接词 / 生理反应短语 / 段尾腔调）、`paragraph-opener`（代词表）、
`stale-state-duration`、`prop-handover` / `prop-relocation`（取件动作词）等。
⚠️ 其中一部分其实是**语法/形式**（代词表、引号族、句末标点）——按上表划界保留；
真正的**题材内容表**（气味、生理反应、终结动词、取件动作）必须改成模型判断。
