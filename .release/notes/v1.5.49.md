# 1.5.49

## 中文

### 修复：移除恢复卡片后切页又长回来

- 右侧「可恢复的内容」单张「移除卡片」和「一键清除全部卡片」过去只写进内存，切页或重开作品后同一批卡片又从运行记录里派生出来。现在两条路径都真正落库，移除后不再复活；正式内容、检查点与运行记录保留不变。
- 修复了持久化「已移除」标记时因缺少事务而静默失败的问题——单张移除的失败过去被界面吞掉，作者看起来就是「点了没用」。
- 修复了「已移除」标记被误判成「作者已编辑」的连带问题：它会让一个还在跑的运行突然被冻结、拒绝继续执行，也会覆盖掉同一条运行上别的作者效果。

### 修复：AI 检查清掉后切页又出现

- AI 检查结果被清掉、或对应粗纲段已被作者删除后，检查面板会显式清空；过去它一直显示内存里那份旧结果，看起来就是「5 条已处理清不掉」。

### 维护

- 更新校验脚本与工作流的仓库地址，指向当前仓库所有者。
- 便携导出/备份字段策略对齐当前 schema，修掉导出时的字段漂移。

## English

### Fixed: recovery cards reappearing after removal

- The per-card "Dismiss card" and the "Clear all cards" actions on the right-hand recoverable list were session-local only: after switching pages or reopening the book, the same cards were re-derived from the run records. Both paths now persist, so a dismissed card stays gone; saved content, checkpoints, and run history are untouched.
- Fixed a silent no-op where persisting the "dismissed" marker failed for lack of a transaction — the per-card failure used to be swallowed by the UI, which looked like "clicking does nothing".
- Fixed the "dismissed" marker being misread as an author edit, which could freeze an in-flight run and reject further execution, and could overwrite other author effects on the same run.

### Fixed: AI checks reappearing after clearing

- When a check's record is cleared, or the outline segment it refers to was deleted by the author, the review panel now clears itself; it used to keep showing the stale in-memory run, which looked like "the 5 handled items cannot be cleared".

### Maintenance

- Updated the update-verification scripts and workflow to the current repository owner.
- Aligned the portable export/backup field policy with the current schema, fixing field drift on export.
