# 1.5.14

## 中文

这一版修粗纲重复、粗纲解析失败，并统一了「细纲」的叫法。

### 粗纲不再重复

- 模型一次多吐后续段时，只保留当前这一段，从第二个段标题处直接截断。
- 已存库的脏数据会在读取时自愈：同一段里混进的后续粗纲会被自动裁掉，不再出现「1–3000 章」后面又接「几百章」的重复。
- 一次调用仍然只生成一段粗纲；生成完再继续调下一段。

### 粗纲解析更宽容

- 标题前后有说明文字、没有井号、没有冒号、第二段写成「第X章至第Y章」都能解析，不再动不动 `ARC_PARSE_NO_SEGMENT`。
- `beat` 行支持 `beat:`、`**beat**：`、`形态:`、`Beat -` 等写法；漏写 beat 时用中性形态兜底，不再整段作废。

### 命名与流程

- 「情节大纲」统一改名为「细纲」，中英文一致。
- 生成弹框与架构页的文案同步更新。
- 细纲生成前会校验粗纲是否已铺满并全部确认；没铺满时直接提示，不会在没有方向的情况下生成细纲。

### 验证

- 粗纲相关测试 41 项全部通过（含多段截断、宽容标题、缺 beat 兜底、仓库自愈）。
- 类型检查与 lint 全部通过。

升级不改动作品数据（脏粗纲会在下次读取时自动裁剪）。

Windows 安装包未签名，系统可能提示未知发布者。

## English

This release fixes duplicated arc segments, arc parse failures, and unifies the chapter-outline naming.

### No more duplicated arc segments

- When the model emits several segments at once, only the current segment is kept; parsing stops at the next segment heading.
- Existing dirty rows self-heal on read: later segments accidentally merged into an earlier one are trimmed.
- One model call still produces exactly one arc segment.

### More tolerant arc parsing

- Headings with preamble text, without hashes, without a colon, or written as "chapter X to Y" are accepted, so `ARC_PARSE_NO_SEGMENT` no longer fires on minor formatting drift.
- `beat` lines tolerate `beat:`, `**beat**:`, `形态:`, `Beat -`; a missing beat falls back to a neutral stage instead of discarding the segment.

### Naming and flow

- "情节大纲" is renamed to "细纲" consistently, in Chinese and English.
- Chapter-outline generation is gated on the arc outline being complete and confirmed.

### Verification

- 41 arc-related tests pass, covering multi-segment truncation, tolerant headings, missing-beat fallback and repository self-healing.
- Typecheck and lint pass.

Upgrading does not touch project data (dirty arc rows are trimmed on the next read).

The Windows installer is not code-signed; Windows may warn about an unknown publisher.
