# 1.5.35

## 中文

### 修复：粗纲编辑后保存报「资源只读或无效」

粗纲是按段存在数据库里的（每段有自己的章范围、beat、状态和修订号），整篇覆盖会丢掉分段结构，所以之前干脆拒绝了整篇写入——但编辑器里仍然显示着「保存」按钮，点下去必报错。现在：

- 在粗纲编辑器里改标题、beat、正文后，**保存真的能写进去**：把整篇 Markdown 解析回各段，按段对回既有记录逐段回写。
- 只有**内容真的变了**的段才会升修订号并回到「待确认」，没改的段一动不动。
- 增删段、改章范围不在这里改：不实现分段结构时会明确报「结构已变化」，而不是粗暴式覆盖；这类改动请用粗纲面板的生成/删除流程。
- 保存成功后标题栏正确显示「已保存」，不再挂着未保存小红点。

### 修复：「AI 重新生成」里没有粗纲选项

- 对话框里现在**列出了粗纲**，并写明它是按段生成。
- 从粗纲编辑器点「AI 重新生成」时，粗纲默认已勾选，按钮直接变成「确认生成粗纲」，不再打开一个生成不了粗纲的对话框。
- 粗纲与其余四节**互斥**（按段生成与整篇生成不是同一条流程），勾上粗纲时其余四节置灰，避免一次提交里混两种工作流。

### 验证

- 在《源起》上真实操作：打开粗纲 → 编辑正文 → 保存 → 界面显示「已保存」，数据库里该段修订号 +1、状态回到待确认，未改动的段保持不变。
- 新增回归测试：Markdown 反解析回分段、整篇保存只改真正变化的段、结构变化时拒绝、对话框列出粗纲且互斥。
- 类型检查、lint、i18n 覆盖率检查全绿。

## English

- Fixed "resource is read-only or invalid" when saving an edited arc outline. The outline is stored as segments, so the whole document is now parsed back into segments and written per segment; only segments whose content actually changed are bumped to draft, and structural changes are refused with a clear message instead of a silent error.
- The "AI regenerate" dialog now lists the arc outline (generated segment by segment) and preselects it when opened from the arc editor; it is mutually exclusive with the other four sections.
